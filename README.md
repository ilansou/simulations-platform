# Artificial Intelligence-Based Platform for Simulation Management and Analysis

[![Python](https://img.shields.io/badge/Python-3.9+-blue.svg)](https://www.python.org/)

## 📖 Overview

In modern scientific and engineering fields, simulations are pivotal for understanding complex systems. However, as systems like data center networks grow in complexity, the volume of simulation data becomes immense. Manually analyzing these vast datasets is time-consuming, error-prone, and a critical bottleneck in research and development.

This platform addresses the challenge by providing a unified, AI-powered solution. It integrates robust **simulation management** capabilities with an intelligent **analysis engine** powered by a locally-run Large Language Model. By leveraging a **Retrieval-Augmented Generation (RAG)** architecture, the platform allows researchers to interact with their simulation results in natural language, asking complex questions and receiving context-aware, data-driven insights.

The project began by building upon two previous projects—one focused on simulation management and another on prompt engineering for data analysis. This platform unifies their strengths, creating a cohesive and powerful tool designed to accelerate the pace of innovation and discovery.

## ✨ Key Features

- **💻 Unified Simulation Management:** Create, configure, run, monitor, and manage `floodns` network simulations through an intuitive web interface.
- **🧠 AI-Powered Analysis:** Interact with a chatbot to ask complex questions about your simulation results in plain English.
- **🔍 RAG Integration:** The LLM is provided with relevant context directly from the simulation's output files (CSVs), ensuring answers are accurate, specific, and grounded in data.
- **📊 Dynamic Prompt Engineering:** The system is designed to be flexible, allowing users to tailor their analyses to specific research questions.
- **🚀 Local First:** The entire stack, including the LLM (via **Ollama**) and the database, is designed to run locally, ensuring data privacy and control.
- **🌐 Interactive UI:** Built with **Streamlit** for a responsive and user-friendly experience, presenting complex data through clear visualizations and text.

## 🏛️ System Architecture

The platform is built on a modular, multi-layered architecture to ensure a clear separation of concerns and scalability.

1.  **Frontend Layer (Streamlit):** The user-facing web interface for managing simulations and interacting with the AI analysis chat.
2.  **Application Layer (Python):** The core business logic. It handles user requests, validates parameters, orchestrates simulation runs, and interfaces with all other components.
3.  **Simulation Engine (FloodNS - Java Core):** The underlying engine that runs the network simulations and generates output data logs (CSVs). The platform uses Python wrappers to execute and manage this engine.
4.  **AI / LLM Layer (Ollama & Custom RAG):**
    - **Ollama:** Serves the `DeepSeek-R1` model locally.
    - **RAG Logic:** When a user asks a question, this layer reads the relevant simulation CSVs, extracts contextual data, and prepends it to the user's prompt before sending it to the LLM.
5.  **Persistence Layer:**
    - **MongoDB:** Stores metadata for all simulations (configurations, status, file paths) and the chat history.
    - **File System:** Stores the raw output files (logs, CSVs, reports) generated by `FloodNS`.

## 🛠️ Installation and Setup

Follow these steps to set up the project environment locally.

### Prerequisites

- [Git](https://git-scm.com/)
- [Python](https://www.python.org/downloads/) 3.9+ and [Poetry](https://python-poetry.org/docs/#installation)
- [Java Development Kit (JDK)](https://www.oracle.com/java/technologies/downloads/) 11 or higher and [Maven](https://maven.apache.org/install.html)
- [Ollama](https://ollama.com/)

### Step-by-Step Guide

1.  **Clone the Repository**

    ```bash
    git clone https://github.com/ilansou/simulations-platform.git
    cd simulations-platform
    ```

2.  **Install Python Dependencies**

    ```bash
    source .venv/bin/activate
    pip install -r requirements.txt
    ```

3.  **Build the Java Simulation Engine**
    Navigate to the `floodns` directory and build the project with Maven.

    ```bash
    mvn clean compile assembly:single
    mv target/floodns-*-jar-with-dependencies.jar floodns-basic-sim.jar
    cd ..
    ```

    This will create the necessary JAR file.

4.  **Set up the Local LLM**
    Pull the required model using Ollama.

    ```bash
    ollama serve
    OLLAMA_NUM_GPU=0 \
    OLLAMA_DEBUG=true \
    CUDA_VISIBLE_DEVICES="" \
    ollama run deepseek-r1:1.5b
    # Make sure Ollama is running in the background.
    ```

    This will start a MongoDB container in the background.

5.  **Run the Application**
    Launch the Streamlit web server.
    ```bash
    streamlit run app.py
    ```
    The application should now be accessible in your web browser at `http://localhost:8501`.

## 🏃‍♀️ How to Use

1.  **Launch the app** by navigating to `http://localhost:8501`.
2.  **Manage Simulations:**
    - From the sidebar, go to the **"Simulation Management"** page.
    - You will see a list of existing simulations.
    - Click **"Create New Simulation"** to define parameters for a new run (e.g., number of jobs, failure scenarios).
    - Click **"Run"** on a configured simulation to start it. You can monitor its status (e.g., `running`, `completed`, `failed`).
3.  **Analyze Results:**
    - Once a simulation is `completed`, navigate to its **"Analysis"** page.
    - A chat interface will be available.
    - Ask questions in natural language, for example:
      - `"What was the average flow completion time?"`
      - `"Compare the bandwidth utilization between the first 10 seconds and the last 10 seconds."`
      - `"Were there any packet drops? If so, which flows were affected?"`
    - The LLM will provide answers based on the data generated by that specific simulation.
